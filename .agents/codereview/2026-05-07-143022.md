# Code Review

## Overview

This change simplifies the Rummikub homepage by removing the "Join Game" input and button, making the only way to join a game via direct URL (e.g., `/lobby/ABC123`). It also adds a shareable game URL display with a "Copy" button (including `execCommand` fallback for insecure contexts) and "Copied!" feedback in the lobby. The PRD and e2e tests are updated accordingly.

## Findings

### [Severity: Low]

**File**: `packages/client/AGENTS.md:12`

**Issue**: The `Home.tsx` description still says "Landing page — create or join a game" but the join functionality has been removed.

**Suggestion**: Update the description to reflect the simplified page:
```
| `src/pages/Home.tsx` | Landing page — create a game |
```

Also update `Lobby.tsx` description to mention the URL sharing:
```
| `src/pages/Lobby.tsx` | Waiting room — share game code/URL, wait for opponent, start game |
```

---

### [Severity: Low]

**File**: `packages/client/src/pages/Lobby.tsx:74`

**Issue**: `document.execCommand("copy")` is deprecated and may be removed from browsers in the future. While it's a reasonable fallback for insecure contexts, the return value of `execCommand` is not checked. If the copy fails silently, the user still sees "Copied!" feedback, which is misleading.

**Suggestion**: Check the return value of `execCommand` and only show "Copied!" on success. If it fails, consider showing an error or not changing the button text:
```typescript
const success = document.execCommand("copy");
document.body.removeChild(textarea);
if (success) {
  onSuccess();
}
```

---

### [Severity: Nit]

**File**: `packages/client/src/pages/Lobby.tsx:61-83`

**Issue**: The `handleCopy` function is wrapped in `useCallback` with `[gameUrl]` as a dependency. Since `gameUrl` is derived from `gameCode` (which comes from URL params and doesn't change during the component's lifecycle), this dependency will never actually change. The `useCallback` is unnecessary here — a plain function would work fine and be simpler.

**Suggestion**: Either remove `useCallback` and use a plain function, or keep it if there's a plan to pass `handleCopy` as a prop to a memoized child component in the future. No action required if the current approach is intentional for consistency.

---

### [Severity: Nit]

**File**: `packages/client/src/pages/Lobby.tsx:134-136`

**Issue**: The text "Share this code with other players" is still present even though the primary sharing mechanism is now the game URL (displayed above). The wording could be confusing — should users share the code or the URL?

**Suggestion**: Consider updating the text to something like "Share this URL with other players" to align with the new primary sharing mechanism, or "Share this code or URL with other players" to reference both.

---

### [Severity: Nit]

**File**: `packages/qa/tests/game-flow.spec.ts:296-309`

**Issue**: TC-28 verifies the Copy button exists and shows "Copied!" feedback, but doesn't verify the actual clipboard content. The test could pass even if the clipboard copy silently fails (especially with the `execCommand` fallback).

**Suggestion**: Consider reading the clipboard to verify the URL was actually copied. In Playwright, this can be done with `page.evaluate(() => navigator.clipboard.readText())` in secure contexts. If this is too fragile for CI, the current approach (verifying visual feedback only) is acceptable as a pragmatic trade-off.

---

### [Severity: Nit]

**File**: `packages/qa/tests/game-flow.spec.ts:306`

**Issue**: The test clicks "Copy" and immediately checks for "Copied!" button text. Since the "Copied!" state reverts after 2 seconds, there's a theoretical race condition if the test is very slow, but in practice this is fine since the assertion happens immediately after the click.

**Suggestion**: No action needed — this is a non-issue in practice.

## Summary

The implementation is clean and well-aligned with the plan. All acceptance criteria from the plan are covered. The code changes are minimal and focused — removing the join UI from Home, adding URL display + Copy to Lobby, and updating tests and docs accordingly. The clipboard fallback for insecure contexts is a thoughtful addition.

Findings: 0 Critical, 0 High, 2 Low, 4 Nit.

The two Low findings are worth addressing: the stale AGENTS.md description for Home.tsx, and the unchecked `execCommand` return value that could show false "Copied!" feedback.
