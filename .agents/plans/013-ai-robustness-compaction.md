# Phase 4.3: AI Robustness — Retries, Failure Policy, Context Compaction

## Goal

Harden the LLM agent from Plan 012 for real-world play: transient API errors are retried with exponential backoff before pausing; malformed model output gets one self-correction chance; runaway tool loops are capped by a configurable iteration limit; and the persistent conversation is **compacted with a running summary** when it grows too large, so long games don't blow the model's context window. All failure paths end in the existing pause-and-surface behaviour (`ai:error` + stuck banner, recover by server restart) — there is no auto-draw and no intervention endpoint, per scope decisions.

Prerequisites: Plans 011 (infrastructure, pause-and-surface) and 012 (LlmProvider, conversation store, logging).

## PRD References

- F-44: AI failures pause the game and surface the error to all players (this plan defines *which* failures pause immediately vs. retry first)
- F-45 (new): The AI conversation is compacted (older exchanges folded into a summary) when it exceeds a configurable token budget
- F-42/F-43: unchanged behaviour — retries and compaction are transparent to the tool protocol and logging

## Scope Decisions

- **Transient error classification**: HTTP 429, 5xx, network errors, and request timeouts are retried. Auth errors (401/403), context-length errors, and anything else pause immediately (retrying won't help; the log message should say so).
- **Retry policy**: up to `AI_MAX_RETRIES` (default 3) retries per completion with exponential backoff `AI_RETRY_BASE_MS` (default 1000) ×2 + jitter (1s, 2s, 4s). Retries are logged (`event: "retry"` with attempt number and error). Exhausted retries → pause-and-surface.
- **Malformed tool calls**: a single invalid tool call (unknown tool, unparseable args) already returns a corrective tool result (Plan 012). This plan adds: if an entire turn's completion contains **only** malformed calls with zero successful ones for `AI_MALFORMED_LIMIT` (default 2) consecutive completions → pause-and-surface (the model is not coping).
- **Iteration cap**: `AI_MAX_TOOL_ITERATIONS` (default 25, was hardcoded 50 in Plan 012). Exceeding it → log + pause-and-surface. If a model legitimately needs more than 25 tool calls for a complex manipulation it will pause — acceptable; raise via env if observed.
- **Compaction** (the main feature):
  - Before each AI turn, estimate the conversation's token count (`Math.ceil(totalChars / 4)` heuristic — no tokenizer dependency; safely handling `null` message content with tool calls)
  - If over `AI_CONTEXT_TOKEN_LIMIT` (default 100000): run **compaction** — replace all messages except the last `AI_COMPACT_KEEP_TURNS` exchanges (default 6) with (a) a generated summary of the removed messages plus (b) a fixed note ("Earlier conversation summarized. Board state is authoritative via `get_game_state`; do not rely on exact earlier tile positions.")
  - **Clean turn boundary & gateway role compatibility**: The slice between older and kept messages must align cleanly to a turn boundary (immediately before a turn-start `user` message) so that an assistant `tool_calls` message is never separated from its required following `tool` messages. To comply with providers enforcing user-first role ordering (e.g. Anthropic/Claude proxied by Zen gateway), the summary is formatted as a `user` context message (`[Summary of earlier conversation]: ...`), avoiding invalid assistant-first turns after the system prompt.
  - The summary is generated by a dedicated completion call (same model, `tools: []`, summarization prompt: moves made, rejected attempts and why, strategy notes). The summarization call itself consumes tokens but only runs when over budget (throttled at most once per turn).
  - If the summarization call fails (transient → retried per policy; then) → **fallback to truncation**: drop the oldest messages wholesale (keeping the note) rather than pausing the game. Log `event: "compaction_fallback"`.
  - Compaction logged (`event: "compaction"` with before/after token estimates)
- **No behavioural change to gameplay**: compaction/summary content must never fabricate game state — the turn-start message and `get_game_state` remain the source of truth.

## Acceptance Criteria

1. A 429/5xx/network/timeout error during any completion is retried up to `AI_MAX_RETRIES` times with backoff; game only pauses if all retries fail
2. Auth/context-length errors pause immediately with a log message indicating the class of failure
3. `AI_MAX_TOOL_ITERATIONS` (default 25) exceeded → pause-and-surface, logged clearly
4. Two consecutive completions containing only malformed tool calls → pause-and-surface
5. A conversation over `AI_CONTEXT_TOKEN_LIMIT` gets compacted before the turn: summary + recent turns; the turn then proceeds normally with the gateway seeing a request under budget
6. Summarization failure falls back to truncation instead of pausing
7. Compaction, retries, and fallbacks are visible in the JSON console logs
8. Scripted provider and normal human play are unaffected

## Edge Cases

- Turn 1 of a game already over budget (tiny `AI_CONTEXT_TOKEN_LIMIT` env) → compaction has nothing to summarize → keep system + turn-start messages only
- Retry succeeds on attempt 2 → no `ai:error`; turn completes normally
- Compaction runs, then the model references "the summary" — fine; summary note tells it to use `get_game_state` for truth
- Two AI players in one game both over budget → independent compaction per conversation
- Backoff delays during an AI turn: human sees "AI is thinking..." for up to ~7s extra per retried completion — acceptable
- Gateway returns context-length error **after** compaction (summary + kept turns still too large, e.g. absurdly low limit) → pauses immediately; documented remedy: raise `AI_CONTEXT_TOKEN_LIMIT`
- Server restart mid-game → all conversations lost with the game (existing in-memory behaviour)

## Implementation Steps

### Step 1: Server — error classification and retry wrapper

- `packages/server/src/ai/retry.ts`:
  - `classifyError(err): "transient" | "fatal"` — inspect openai SDK error status/code (429, >=500, ECONNRESET/ETIMEDOUT/ENOTFOUND, timeout aborts → transient; 401/403/context-length/others → fatal)
  - `withRetries(fn, { maxRetries, baseMs }, onRetry): Promise` — exponential backoff + jitter; invokes `onRetry(attempt, delay, error)` for logging
- `config.ts`: add `AI_MAX_RETRIES` (3), `AI_RETRY_BASE_MS` (1000)
- `LlmProvider`: wrap every `chat.completions.create` (main loop AND summarization) in `withRetries`; fatal errors throw immediately; log `event: "retry"` per attempt and rethrow the last error when exhausted

**Tests** (`retry.test.ts` + provider tests):
- Transient error twice then success → succeeds, 2 retries, correct delays (fake timers)
- Transient errors `AI_MAX_RETRIES`+1 times → throws last error
- Fatal (401) → immediate throw, no retry, no delay
- Provider logs retries; exhausted retries reach the runner's pause path

---

### Step 2: Server — configurable iteration cap + malformed limit

- `config.ts`: `AI_MAX_TOOL_ITERATIONS` (25), `AI_MALFORMED_LIMIT` (2)
- `LlmProvider` loop: replace hardcoded 50 with the env; track consecutive completions where zero tool calls succeeded and ≥1 was malformed → pause after `AI_MALFORMED_LIMIT`; log clearly in both cases (`event: "error"` with `data.reason: "iteration_cap" | "malformed"`)

**Tests:** cap breach at 25 throws with reason `iteration_cap`; two all-malformed completions throw with reason `malformed`; a success resets the malformed streak.

---

### Step 3: Server — token estimation and compaction

- `packages/server/src/ai/compaction.ts`:
  - `estimateTokens(messages): number` — chars/4 across message contents (safely guarding against `null` content) + stringified tool calls
  - `needsCompaction(messages, limit): boolean`
  - `compact(conversation, client, { keepExchanges, model, gameCode, playerId }): Promise<ChatMessage[]>`:
    - Split into `older` (system prompt excluded) and `kept` (last `keepExchanges` request/response exchanges, aligned to turn boundary before a `user` turn-start message)
    - Summarization prompt → summary completion (with retries; `tools: []`, low `max_tokens` e.g. 2000)
    - Return `[system, user("[Summary of earlier conversation]: " + summary), note, ...kept]` (gateway role compatible)
    - On summarization failure → `[system, note, ...kept]` (truncation fallback) with `compaction_fallback` log
- `config.ts`: `AI_CONTEXT_TOKEN_LIMIT` (100000), `AI_COMPACT_KEEP_TURNS` (6)
- `LlmProvider.takeTurn`: before pushing the turn-start message, `needsCompaction` → `compact` → log `event: "compaction"` (before/after estimates, mode: `summary | fallback`)

**Tests** (`compaction.test.ts` + provider integration):
- Under limit → untouched
- Over limit → summary call made with the older messages serialized; result keeps system prompt + summary + note + last K exchanges; token estimate under limit
- Summarization throws → fallback truncation keeps note; no error thrown
- Empty/short conversation over a tiny limit → nothing removed but note preserved; no crash
- Compaction happens at most once per turn (second `needsCompaction` check after compaction returns false for reasonable limits)

## Validation Steps

1. **Automated**: unit tests, typecheck, lint, e2e suite (scripted provider) pass
2. **Manual (real model)**:
   - Play a long game (or set `AI_CONTEXT_TOKEN_LIMIT` artificially low, e.g. 20000) against a real model; verify `compaction` events in logs and that play continues sensibly after compaction
   - Temporarily set `AI_API_KEY` to garbage → verify immediate pause with a clear "auth" failure message (no long retry storm)
   - Use a free/small model and watch for `retry` events under gateway load; confirm backoff and recovery
   - Confirm a game where the model loops (small model + complex board) ends in the stuck banner rather than an infinite loop
